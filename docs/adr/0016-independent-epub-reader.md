# Add an independent EPUB Reader to Edison

**Status: accepted (2026-10-13); stages 0–5 locally validated; stage 6 deployed and production smoke-tested (2026-10-15).**

Reader will be a separate Edison navigation destination with a full main-area reading view. Books, reading positions and annotations will belong to the owner's Edison server, rather than depend on an ongoing Readwise service connection. The first release handles newly imported EPUB books and the complete import, Inbox/Later/Archive, reading/resume, highlight/note, search and export loop; acceptance initially covers the current computer.

PDF, existing Readwise-data migration, offline operation and cross-device acceptance are outside this first release. Reader initially does not absorb YouTube manuscripts or classroom documents, so the workbench's Markdown handoff remains intact. Readwise Reader is the subject of behavioral and client analysis; the resulting interface adapts to Edison rather than requiring a visual clone. Stage 1 persists immutable originals and library identity/placement. Stage 2 persists an exact stopping anchor, furthest reached position and per-book layout preferences, with optimistic concurrency and idempotent retry. Furthest reached includes deliberate jumps and does not assert reading completion. Reflow does not advance it. Stage 3 persists full-range highlights, book/highlight notes and Notebook navigation with per-book revision conflicts. Unverifiable quotes remain visible as needing repair, without being painted or silently relocated. Stage 4 adds literal, case-sensitive current-book text search and saved library note/highlight search, with verified jumps and transient search outlines separate from annotations. Markdown and JSON export a consistent saved-server snapshot. JSON preserves identity and locators without claiming anchor validation or providing import/restore. Search targets are consumed once so later reloads resume normally. Stage 5 validates the full loop through local HTTPS/Caddy, normal server startup and cookie login, including forced backend termination, restart and authentication-expiry retry, with synthetic and private EPUBs in three browser engines. Stage 6 deploys the isolated Reader candidate to the existing server and validates normal Zen login, synthetic EPUB import, saved notes, refresh, search and actual downloads. Production credentials and private books are not included in the evidence. See [production release](../research/readwise-reader/stage6-release.md). See [full-loop validation](../research/readwise-reader/stage5-validation.md). See [search/export validation](../research/readwise-reader/stage4-validation.md). See [annotation validation](../research/readwise-reader/stage3-validation.md). See [resume validation](../research/readwise-reader/stage2-validation.md).

The initial supported profile is reflowable EPUB 2/3 with HTML/XHTML spine resources. Fixed-layout and standalone image/SVG chapters are rejected explicitly. Foliate-js is pinned; rendered/searchable content shares one sanitization rule, and content identity includes that rule version. This narrows compatibility to preserve trustworthy future text anchors. See [validation](../research/readwise-reader/stage1-validation.md).
