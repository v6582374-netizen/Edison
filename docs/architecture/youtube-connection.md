# YouTube 连接与账号订阅同步

> 本文保留旧桌面实现的连接、Keychain 与 Vault 迁移说明，不是当前自托管 Web 产品的目标架构。现行边界见 ADR 0013、ADR 0017，以及[已确认的迁移决策](https://github.com/v6582374-netizen/Edison/issues/46#issuecomment-6258668775)。下文旧桌面说明不代表当前受管理 Web 路径；不能据本文推断服务器应依赖本机 Keychain，或旧迁移接口将继续保留。

## 受管理 Web 的断开边界

设置 `EDISON_CONTENT_SESSION_DIR` 后，Web 的“断开 YouTube”同时撤回官方授权和内容会话。先持久化撤回意图，使在途 OAuth 操作的代次失效；本实例清除用户客户端配置、令牌、专用 profile、当前快照及消费者副本。独立字幕进程按会话代次检查一次性副本的使用许可，即使文件删除失败也会停止，不接受迟到结果。订阅分页和 Shorts 回退请求在每次外部请求前重新检查许可，迟到的分页信息不能继续使用旧身份。浏览器关闭或存储清理失败会显示本地清理失败，仍禁止使用旧身份，重启继续清理。

Google 平台撤销是独立结果：成功、失败、没有可用授权或中断后未知，不能由本地清除推断。平台请求在本地停止使用之后进行，失败不恢复凭据；平台撤销未完成时不接受新的官方交接。已有知识资产、字幕、译文、版本、阅读记录、取消和 Auto Update 选择均保留。重新上传官方授权交接文件、打开服务器登录画面都是明确的新连接意图，不修改执行许可。

受管理 Web 拒绝旧 `session_cookies.replace/test`、`connection.migrate_credentials/configure/authorize` 请求并提示刷新及使用新入口；可信设备首次 OAuth 交接仍使用 `connection.import_authorization`。独立 CLI 的配置、授权及显式 Vault 迁移保留，不能与正在持有同资料库租约的 Web 写者并行使用。旧生产 Cookie/Vault/原型路径的清理属于后续受控迁移，不由该接口扫描或删除。

隔离 Web 测试使用真实宿主循环、临时持久资料库及独立字幕子进程，外部 Google/YouTube、模型和时间受控。它们证明断开、重连、旧入口拒绝及迟到结果失效，不证明真实 Google 撤销、生产迁移、资源准入或长期验收。

## 历史桌面连接

Edison 使用 Google 的桌面 OAuth 流程（浏览器、随机 loopback 回调、state 校验、PKCE、只读订阅权限）。日常使用不依赖 Automic Vault。

- 刷新令牌与自定义客户端配置由系统凭据存储保存，macOS 使用 Keychain。整个连接记录一次写入；存储失败不会退回明文文件。
- 短期访问令牌仅保存在进程内存。重启后自动使用刷新令牌换取新令牌。资料库路径决定凭据命名空间，正式版与开发版相互隔离。
- 查看连接状态只读本地的非敏感状态，不读取密钥、不启动浏览器。实际同步才使用凭据；并发同步合并，令牌失效先尝试续期，明确撤销或 `invalid_grant` 才要求重新登录。
- 订阅页展示本地列表并提供显式同步。Auto Update 开启时，独立后台线程每六小时同步名单，不受长时间文稿生成阻塞；视频发现独立每五分钟检查。
- 必须拿完所有分页才提交新清单。网络错误、非法响应、分页重复不改变已有订阅。取关取消未开始且无文稿的准备任务，阻止迟到的旧扫描 再次入队；进行中的任务和已有文稿保留。
- 旧桌面流程原先只清除本资料库的令牌；当前连接服务断开时也清除用户客户端配置，阅读资料仍保留。授权被撤销只影响同步，不删除本地内容。

## 旧连接迁移

连接能力提供明确的一次性迁移操作。迁移只读取旧 Vault 中这个资料库的账号令牌，OAuth 客户端配置可复用旧全局配置；不会读取其他资料库或旧独立工具的全局账号令牌，不修改旧 Vault 或旧资料库。一次授权批量取得所需字段，在内存中交接到系统钥匙串。完成后重复调用不再访问 Vault。

## 正式发行的 Google 客户端

Google OAuth 客户端必须由产品开发者在 Google Cloud 注册为 Desktop app，并启用 YouTube Data API、配置 consent screen。它不是模型能够生成的有效配置。测试模式和公开发布、Google 验证及 API 配额均由该项目管理。

构建时设置 `EDISON_GOOGLE_OAUTH_CLIENT_ID` 和 `EDISON_GOOGLE_OAUTH_CLIENT_SECRET`，PyInstaller 将开发者指定的桌面客户端配置作为应用资源打包。构建过程不自动读取本机 Vault、Keychain 或用户账号令牌。两项必须同时设置；它们是桌面应用配置，不能当作保证机密的客户端身份凭证。

有该配置的发行版直接显示浏览器授权按钮，无需普通用户输入 ID/Secret。缺少该配置的开发构建可在连接表单中提供自定义客户端。迁移能力只接受用户明确请求；不会在启动时扫描旧凭据。

## macOS 签名

Keychain 访问通过 Security.framework 完成，凭据不通过命令行参数传递。正式发行应使用稳定的 Developer ID 签名维持访问身份。当前 ad-hoc 开发构建在二进制身份变化或钥匙串被锁定时，macOS 仍可能要求系统级确认；页面导航不会反复发起 Vault 审批。
