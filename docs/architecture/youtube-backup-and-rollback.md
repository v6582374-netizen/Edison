# YouTube 一致性备份、恢复与程序回退

本文说明[YouTube：一致性备份与保留最新数据的恢复演练](https://github.com/v6582374-netizen/Edison/issues/57)交付的维护动作。决策依据见 ADR 0018、ADR 0019 与[迁移决策](https://github.com/v6582374-netizen/Edison/issues/46#issuecomment-6258668775)。

## 两种动作，不可互换

- **程序回退**（常规）：在**最新资料库**上运行较早的程序，不恢复任何快照。只允许数据契约覆盖资料库的程序；不兼容就保持当前能读取最新资料的服务，采集停在切换暂停。
- **备份恢复**（灾难）：资料库损坏或丢失时，把一致性备份恢复到**空目录**。恢复结果是备份时刻的资料，之后的文稿、阅读、取消、Auto Update 选择不在其中；恢复后采集保持切换暂停，界面显示“已从一致性备份恢复”。恢复工具拒绝写入非空目录，不会无提示覆盖最新资料。

`scripts/promote_web_release.py` 只切换静态前端文件，不是后端、资料或凭据回退。

## 取得一致性备份

1. Web“维护工具”中开始切换暂停，等待状态显示在途成果已保存、写者已结束（`drained`）。
2. 点击“取得一致性备份并验证恢复”。未完成收尾时会拒绝；备份期间若有任何新的准入工作（包括用户撤回操作），本次备份作废，收尾后重做。
3. 备份默认写到资料库旁的 `youtube-backups/`（`EDISON_YOUTUBE_BACKUP_DIR` 可改），目录 0700，只含 `workspace.sqlite3`、`assets/` 与 `manifest.json`。凭据文件、内容会话 profile 与快照不复制；拒绝作为符号链接的 `assets/` 根目录，其中的符号链接不跟随；资料库根目录的其他文件只在清单中按名称列出。
4. 备份完成后立即恢复到同目录下的临时目录比对：数据库原始文件哈希、完整性检查、全部行（路径按资料库相对化）的摘要、知识文件哈希、每篇当前文稿可读、字幕可用、引用的文件都在资料库内。恢复验证结束再检查一次写者准入代次，验证期间的新操作也使本次备份作废。结果写入清单并在界面显示。

## 灾难恢复

在服务停止时执行：

```sh
python -m youtube_strataread.workbench.recovery verify <备份目录>
python -m youtube_strataread.workbench.recovery restore <备份目录> <空的资料库目录>
```

恢复后用正常服务身份启动，通过“阅读文档”核对资料。凭据与内容会话仍是独立管理的当前状态，不随资料回到备份时刻；资料库中的“已授权”标记来自备份时刻，只是历史记录，实际能力仍需重新验证。

## 程序回退

```sh
python -m youtube_strataread.workbench.recovery check-program <目标程序源码根> <资料库目录>
```

退出码 0 才可切换后端程序。目标程序未声明数据契约（本票之前的所有版本）或契约低于资料库时拒绝。若仍误启动了较旧但声明契约的程序，它只提供阅读，采集与连接变更保持暂停，也不会执行迁移或备份。

修改资料库含义、使较早程序可能误读或违背较新用户意图时，必须提高 `YOUTUBE_DATA_CONTRACT`；只增加旧程序可忽略的列不需要。

## 已验证与未验证

隔离 E2E（`surfaces/gui/e2e/youtube-recovery.spec.ts`）从真实 Web、宿主后台队列和临时持久资料库验证灾难恢复后的阅读、历史程序回退拒绝、当前程序重启以及不兼容程序启动时保留崩溃前的任务事实，只控制 Google/YouTube、模型和时间。

历史后端 `02d2c84` 未声明数据契约，已实际提取其源码并验证拒绝回退；当前服务仍能读取最新资料、采集保持暂停。尚无早于本票且声明契约的真实旧版本，因此**没有已验证可运行的历史兼容后端版本**。同契约当前源码检查和重启只构成重启证据，不宣称完成历史兼容程序回退。尚未在生产主机、真实服务身份和生产数据上执行任何演练。
