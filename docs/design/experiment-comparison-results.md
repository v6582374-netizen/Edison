# Edison 隔离翻译对照：方法、证据与替换建议

本报告对应[隔离对照规格](https://github.com/vincentshuo/Edison/issues/68)与[真实对照工作票](https://github.com/vincentshuo/Edison/issues/76)。固定生成矩阵已完成：主矩阵 21 次中 16 次 ready、5 次失败，独立分段实验 4 次均 ready。三种方案均未交付约 4 小时来源的完整成稿；约 2 小时来源只有 B ready。50 个 artifact 结果位的自动评价及离线证据重验已结束。ready 或结构覆盖不等于语义通过；现有证据不足以支持替换，建议保留生产现状并另行限定后续设计。

## 固定代码与处理机制

真实运行固定于 `d6149d2fd7286ddf8b8616b0be3b5885069ed878`，保留的 translation-agent 上游为 `e0fc605acbb5d78cb7a58a98bc8bd8f0056df49c`。运行入口沿用 `PreparationService`、`HostManuscripts`、真实字幕规范化和隔离持久化；只注入字幕获取与模型边界。完整译文和阅读稿分别保存。实验未授权生产部署、历史生产任务重跑或最终架构决策关闭。

| 方案 | 翻译与成稿机制 | 输出与覆盖凭据 |
|---|---|---|
| A | `A-comparable-three-stage`：保留上游初译、反思、修订，再逐章调用既有成稿逻辑 | 独立修订译文与阅读稿；来源范围由宿主按章关联，不是模型返回的逐 cue 覆盖证明 |
| B | `B-direct`：一次忠实翻译每章，再确定性添加标题与分段 | 独立译文与阅读稿；返回 ID 必须完整、有序且不重复，结构覆盖不证明语义完整 |
| C | `C-conditional`：B 加入有次数终止条件的局部自动检查与修复 | 保留局部检查、修复与拒绝证据；有数字或否定等信号不等同于已证实错误 |

三者对同一来源使用相同保守规范化、完整来源语境、实际章节计划和请求输出分配。比较身份包含来源、规范化、模型及代理、共同设置、分段设置与实际章节计划哈希。仅匹配身份的运行可作为成对机制证据。A 的 XML/纯文本提示会重复指定章节，B/C 使用 JSON/来源 ID，输入表示和提示开销不同；调用量或 token 差异不能全部归因于移除反思、修订。

`A-current-baseline` 仍作为独立的当前路径诊断，保留上游原有切分；它不混入本次主机制矩阵。A-comparable 不另切修订译文，也不修改上游全局分块参数。A 的既有成稿验证仍可能因数字字面写法变化而拒绝输出，这是所测基线行为的一部分。

## 有限矩阵与执行顺序

主矩阵计划为 6 份来源 × A/B/C 各一次，再对 short-1 各重复一次，共 21 次生成尝试。重复提供同源随机变化观察，不增加独立来源样本数。计划在运行前冻结，不根据结果修改提示、参数、来源或章节。最终测量为 v4；开发试跑与中止的旧 v2/v3 尝试单独保存，排除于最终矩阵分母。v3 开发数字样本暴露了单层 JSON 代码块兼容问题，最终代码仅接受完整单层 json 外壳并继续强制内部 schema、来源 ID、顺序和结束原因。约 2 小时来源在停止 v3 前已开始并暴露于协议故障，因此保守改标为开发、used_for_tuning=True；它不再是独立留出验证。短英语 short-2 和约 4 小时来源保持留出，校准没有查看其输出正文，最终冻结后不继续调参。

每个固定来源/重复组内最多并行运行 A/B/C 三个尝试；本组全部结束才开始下一来源组。索引保存每臂 UTC 开始/结束时刻、实际提交顺序和结果。相同代理的排队、共享容量与并发竞争可能影响时延；主矩阵 wall-clock 数据不能用来宣称无竞争条件下的纯机制加速。

独立分段实验固定中文开发来源和 B，其余模型、提示、规范化、完整上下文与分配保持一致。四次按 `整份 1 → 两章 1 → 两章 2 → 整份 2` 串行执行。两章边界为 cue 148 和 251，cue 148 在 362.598 秒结束，具有句末标点，下一 cue 为原有小节标题。该四次实验只比较输出分段，不合并进主机制效果统计。

## 自动质量评价

评价协议 `whole-source-selector-observations-v2` 在主生成前冻结。对每个 ready 结果，分别向同一配置模型提供全部保留来源 cue 与一份完整输出（完整译文或阅读稿），前提是渲染后输入不超过已验证字符界限。超过界限、未生成输出、评价调用失败或缺少可靠证据时记为未知。每个 ready artifact 最多一次评价请求，不追加修复评价调用。

每份译文和阅读稿分别报告十个维度：遗漏、增添、数字、单位、否定、限定条件、术语、实体、论证顺序、可读性。模型每维只能返回一个局部 `no_issue_observed`、`issue_observed` 或 `unknown` 观察。它选择精确来源 cue 范围和输出段落 ID，宿主从不可变原文解析为确切引文，再调用现有严格证据验证；不容许通过空白归一化或改写引文制造对齐。无效的一个维度变成未知，不抹掉其他有效观察。

局部观察不等于整篇通过。遗漏/增添的缺失断言需要足够包围语境与具体命题；单一短语不能证明论证顺序。字面数字写法不同本身不是语义错误。评价模型与生成模型相同，相关错误与偏差可能相同；精确对齐保证证据来自原材料，不能保证判断推理正确。字幕可能含 ASR 错误，未核对音频；没有人工语义核对队列。

结果将逐来源、方案、artifact、维度显示局部观察与未知原因，并附评价实际数量、无效证据与评价失败计数。所有真实材料的 `whole_artifact_semantic_status` 保持未知，`semantic_fidelity_certified` 保持 false；即使提供了全文，也不能把每维一个观察变成全文无遗漏证明。

## 代码与确定性验证

固定代码通过 214 项相关确定性测试及 Ruff 检查；测试主要驱动已确认的完整处理入口，使用真实规范化、宿主生成和隔离版本存储，模拟外部字幕/模型响应。覆盖来源保留、无讲话字幕零生成、完整译文独立保存、输出结构/结束原因、输入能力、无累计消费上限、有限重试、恢复、取消、兼容身份与原子发布。

最终代码审查标准轴无发现；规格轴两项发现已在固定代码中修复，并由独立审查者的 8 项定向复核重新验证：中文逐位年份/小数引起的数字误信号在明确语义接受后不再成为硬拒绝；中断后重放已缓存但被拒绝的修复响应不会因遗失响应上下文而永久零调用卡住。后续开发兼容校准另验证了完整单层 json 外壳的有界解码，不接收周围说明、多块、其他标签或不完整 JSON。合成用例证明这些行为，不能代替真实长内容质量结果。旧试跑没有追溯改写为新代码结果。

## 结论与下一步边界

**替换证据不足，保留现有生产机制。** 这是一项完成的有限比较所支持的保守决策，不是证明现有机制质量最好：A 本身在两小时数字字面 guard 和四小时成稿 guard 上失败；B 虽然请求少、两小时可发布，却在四小时结构契约上失败，且已完成两小时产物有局部遗漏/可读性指控；C 在两个长来源均因有限复核未解决而未发布。本次没有四小时完整交付，也没有论证顺序或全篇语义正确性证据，无法确认任何候选满足长期完整阅读稿替换要求。

下一轮应另行限定设计范围：围绕实际长输出协议/结构失败、成稿完整性与基线数字字面 guard、复核未解决后的恢复边界，以及评价维度协议可靠性提出可验收方案。保留此次固定结果，不继续在本轮上调参直至胜出；新的机制修改需要新的独立留出证据。此次报告不部署、不重跑生产历史、不修改既有验收记录，不关闭[最终架构决策](https://github.com/vincentshuo/Edison/issues/67)。
