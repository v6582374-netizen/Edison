# Reader 阶段 4：检索与导出

2026-10-15。承接[批注闭环](./stage3-validation.md)。本阶段在本地生产 GUI 与隔离真实 FastAPI 中实现；没有提交、推送或部署。后续已完成本机完整闭环与正常 Web 部署入口验收，见[阶段 5 验收](./stage5-validation.md)；生产实例发布后验收仍未进行。

## 产品契约

书库保留书名/作者筛选，并增加全库已保存摘录与笔记查找，涵盖 Inbox、Later、Archive。整本笔记、摘录、高亮笔记分别标明来源；同一字段包含多次查询文字时只返回一个条目。结果按稳定的书籍、章节与范围顺序分页，每页 50 条。暂不做全库全部书籍正文的联合搜索与相关性排名。

打开书后可查找当前书正文。采用原文子串匹配，区分大小写，不进行正则、分词、简繁转换或重音归一化；中文、emoji、组合字符及跨标签文字保留原始身份。每次最多显示 200 个位置，达到上限明确提示缩小范围；没有将截断结果显示为全书总数。

正文命中会回到对应范围并显示临时轮廓。查找不会创建、改变或删除高亮。打开搜索列表本身不推进阅读记录；主动点击命中后的导航仍遵守“最远到达”的既有规则。窄屏点击结果后收起查找面板，让正文可见。

全库笔记结果按书籍 ID 与高亮 ID 打开，再读取当前服务器记录。不存在的旧高亮结果显示明确提示，不误跳到同名书或相同句子。跳转目标完成后从当前 URL 清除，后续翻阅与刷新继续使用停读记录，而不会反复被旧搜索目标拉回。

结果定位必须通过内容版本、章节、CFI、完整摘录与正文偏移核对。正文被隐藏或无法显示时，即使字符串匹配也不声称定位成功。查询被替换、面板关闭或书籍退出时，过期结果不应覆盖新请求。

## 导出契约

Notebook 提供 Markdown 与 JSON 下载。两者均读取服务器已经提交的记录；本页笔记未保存、请求进行中或保存失败时不允许导出，避免把旧记录伪装成本次编辑的成果。其他页面可以继续保存，导出得到的是请求时服务器的一致快照，不保证等于某个陈旧页面的显示。

服务器在同一 SQLite 读事务中取得书籍、阅读记录和 Notebook；导出不增加任何修订号。下载沿原有认证边界，使用附件响应、no-store 和 nosniff；失败时不生成空的“成功文件”。原 EPUB 继续通过原有原书下载独立保存。

### JSON v1

JSON 包含 `format: edison.reader`、`version: 1`、导出时间、完整书目与内容版本/原书散列、阅读记录、Notebook（整本笔记、所有高亮 ID、颜色、完整范围和高亮笔记）。UTF-16 偏移口径沿用既有锚点，不转换为百分比。

导出保留所有记录，包括待修复锚点，不悄悄丢弃它们。服务端不运行浏览器排版核对，明确标记 `anchor_validation: not_performed`。完整文件已重新 JSON 解析，并在实际渲染的原书中解析导出的 CFI，核对摘录、前缀偏移和正文长度。

JSON 与匹配的原 EPUB 一起保留定位身份。**本阶段没有 JSON 导入/恢复入口，也没有宣称完成备份恢复产品。**

### Markdown

Markdown 用于阅读和整理：书名、作者、内容版本、Notebook 修订和高亮数量、整本笔记、按章节顺序排列的摘录与笔记。保留高亮 ID 以便与 JSON 对照；章节序号来自 EPUB 内容资源顺序，不冒充书内作者的章节编号。

书目、摘录与笔记按纯文本转义 Markdown 控制字符和 HTML，换行保留。这样不会把书内标题或笔记中的 `<script>`、链接语法当作可执行内容。Markdown 不包含完整定位器，不是完整恢复载体。

## 上游复用与修复

继续执行固定 Foliate-js 的 `searchMatcher` 与 `textWalker`，在与渲染相同的清洗后章节文档上产生 DOM Range，再使用原有 CFI 与原文核对；命中轮廓使用其 Overlayer，未再造分词器、DOM 遍历或排版内核。

E2E 复现了固定上游 `simpleSearch` 的末尾边界错误：查询恰好结束于最后一个文字节点末尾时，原循环继续寻找不存在的下一节点。新增一处精确匹配补丁，将结束边界留在当前节点的末尾。连同前阶段五处分页器生命周期保护，共六处固定版本源码修正；开发与生产均应用，上游不匹配时阻断构建，没有手改 node_modules。

上游 excerpt 字段不是本产品摘录身份来源；列表文字来自经过核对的 Range 与正文偏移。这避免把另一个规范化字符串的显示片段误当成定位依据。

## 验证

最终验收结果：Reader 在 Chromium、Firefox、WebKit 中共 **84 项 E2E 全部通过**（原有 66 项与本阶段新增 18 项），没有跳过可选真实书与布局回归；Reader 后端与认证共 **50 项通过**，课程归档 E2E **11 项通过**，前端认证 **2 项通过**。TypeScript 与生产构建通过；构建仍有既有的大 chunk 提示。`git diff --check` 通过。主要新增验收包括：

- 中文跨标签、English、emoji 和组合字符；两处相同句子分别定位；章节最后节点命中。
- 全库跨书、归档笔记查找；整本笔记和高亮笔记分别打开；过期删除结果；跳转后继续阅读并刷新。
- JSON 真正下载与重新解析，定位器对原文核对；Markdown 摘录数量、ID、Unicode、HTML 转义与换行；未保存编辑及 401 下载失败。
- 搜索轮廓与持久高亮并存，字号/宽度变化和关闭面板后可见；查找不更改 Notebook。
- 200 条上限、无结果、隐藏文字不假装定位成功、替换查询、延迟旧响应丢弃与真实认证失败。
- 后端三类笔记检索、分页、字面符号、大小写、删除后搜索、空 Notebook、未知书籍、认证与参数边界。

所有 Reader E2E 均使用真实导入入口、生产 GUI 和临时 FastAPI 数据库。故障与旧响应场景只拦截被测请求，正常检索、保存和导出不以 mock 成功代替。原有真实中文书、EPUB2、竖排、RTL 和内嵌字体的阅读/批注测试仍作为回归运行。

视觉检查已查看书库跨书笔记结果、宽屏正文命中及窄屏回跳：来源、状态与按钮清楚，临时定位轮廓与黄色高亮可区分，窄屏正文没有被搜索面板遮住。Markdown/JSON 另外核对实际下载文件内容，不以截图代替数据一致性检查。

完整日志、下载样本及截图保留在本机调查目录 `ReaderAnalysis-20261013/evidence/stage4-final/`；定位末尾和一次性目标的失败证据保留于 `stage4-*-before/`。私有书与其截图仅留本机。验收后确认 8791/5199 无监听、测试运行器与 Reader 测试服务器已退出；本阶段未打开可见窗口或预览面板。
