# Reader 阶段 3：高亮、笔记与 Notebook

2026-10-15。承接[可靠续读](./stage2-validation.md)，本阶段在本地生产 GUI 与隔离真实 FastAPI 中实现并验收。尚未部署、提交或推送；本文记录阶段 3 的历史验收；后续检索与结构化导出已完成，见[阶段 4 验收](./stage4-validation.md)。

## 交付范围

从书内选中文字后可以添加高亮，支持黄、绿、粉三色。高亮对应完整的原文范围，拥有独立身份；同一范围再次选择会回到已有高亮，部分重叠的范围可以分别保存。颜色、笔记的变更不会改变范围身份。

Notebook 收集整本笔记与高亮笔记；笔记以纯文本明确保存，不混入书籍正文。条目按章节和文字位置排序；点击摘录回到原文，点击正文的高亮打开对应笔记。窄屏回跳后自动收起 Notebook，避免遮住原文。删除高亮前有明确确认，同时删除其附属笔记，整本笔记不受影响。

高亮不是延长的停读位置：停读位置可用短摘录核对起点，高亮必须核对整个范围。本阶段复用同一内容版本、章节身份与文字端点规范化，但为高亮保留完整摘录。

## 保存与原文契约

- 每本书一个 Notebook 快照，包含整本笔记、高亮列表与独立修订号；书库归类、阅读记录互不占用这个修订号。
- 使用同一 SQLite 原子事务保存整本快照。当前选择了简单、保守的整本并发控制：两个页面即使编辑不同高亮，旧修订也会被拒绝，不做未经确认的自动合并。
- 每次操作保留唯一身份及完整载荷摘要。响应丢失后重试相同操作不会重复写入；若服务器已经有后续更新，旧请求返回冲突，不复活已删除条目。
- 明确点击“保存笔记”后，只有服务器确认才显示同步成功。未保存编辑、进行中写入及失败请求会阻止站内离开，并注册浏览器离开提醒。保存失败时编辑仍留在当前页；没有离线持久队列。
- 请求结果未知时不允许“放弃编辑”仅清空输入框：可重试，或明确采用服务器笔记。后者会放弃本页编辑。普通尚未提交的编辑可以直接放弃。
- 高亮锚点保存 CFI、章节、完整摘录、正文前缀 UTF-16 偏移和正文长度；创建、读取绘制、回跳时均核对原文。同一句话在不同位置不会因摘录相同而合并。
- 核对失败时显示“待修复”，不绘制错误高亮，不用百分比代替；原摘录和笔记保留且仍可查看。此阶段没有自动重新锚定或人工重绑界面。
- 服务端校验认证、版本、章节索引边界、字段形状、重复身份/CFI、颜色与载荷限制；CFI 与 DOM 原文的对应由前端核验。没有把前端核验冒称为服务端独立 EPUB 排版校验。

当前限制：单次高亮属于一个章节，最多 12,000 个 UTF-16 单位；高亮笔记 20,000、整本笔记 50,000 字符上限；每本最多 2,000 条高亮，Notebook JSON 不超过 8 MB。前端输入长度约束按浏览器 UTF-16 计数，后端笔记长度按 Unicode 字符计数。超过上限明确拒绝，不截断保存。

## 验证与证据

最终结果：Reader 三浏览器 **66/66**（新增 Notebook 30 项、原有书库与续读 36 项），Reader Python **36/36**（Notebook 11 项、阅读记录 12 项、书库 13 项），Curriculum E2E **11/11**，前端认证 **2/2**，原有 Reader/网页登录 **6/6**；TypeScript/Vite 生产构建通过，仅保留既有大 chunk 提示。所有 Reader E2E 通过真实产品导入入口、生产构建和临时服务器数据库执行；仅失败场景拦截目标请求，正常保存不是 mock。

| 场景 | 验收内容 |
|---|---|
| 原生鼠标选择 | 中文、跨标签、English、emoji 与组合字符；完整范围保存、重叠高亮、重复选择与正文点击 |
| 编辑与恢复 | 高亮笔记、整本笔记、颜色、删除、字号重排、刷新恢复、跨章节回跳、窄屏原文可见 |
| 故障与并发 | 断网前提交失败、提交后响应丢失、真实 401、双页面冲突、未保存离开提醒、显式采用服务器与放弃未提交编辑 |
| 原文失配 | API 写入失配摘录后重开，显示待修复、不绘制、不覆盖已有记录 |
| 实际书与特殊排版 | 本机实际中文 EPUB、竖排、RTL、内嵌字体的范围保存/重排/刷新/绘制核对 |
| 后端 | 数据库重新打开、独立修订号、修改与删除、响应丢失重试、并发首写、陈旧写入不复活删除、版本/字段/认证边界 |
| 原流程回归 | 书库、续读及布局场景全部重跑；Curriculum 档案、前端认证与原有 Reader/网页登录 |

六个核心 Notebook 场景在每个浏览器中使用真实鼠标拖选。实际书和三种特殊布局场景使用渲染文档里的真实 DOM Selection 产生范围，随后从界面操作并核对服务端；不把这些扩展场景称为逐一验证过原生拖选手势。Firefox 自动化也不等同于在 Zen 应用本体重新验收。

本轮视觉检查已查看宽屏 Notebook、窄屏回跳后的原文、保存失败、待修复条目和实际中文书的高亮。范围覆盖与原文相符，主要按钮可见，侧栏可滚动；清除了保存后残留的系统选择底色，避免遮住高亮颜色。未宣称完整手机端或触摸选择验收。

本机证据保留在 `ReaderAnalysis-20261013/evidence/stage3-*`。失败证据包含响应未知时错误可用的“放弃编辑”；修复后同一 E2E 断言验证。私有书及页面截图不提交公开仓库。

## 重跑

从 Edison 根目录开始：

```sh
.venv/bin/pytest tests/test_reader_notebook.py tests/test_reader_reading.py tests/test_reader_library.py -q
cd surfaces/gui
npm run build
npx playwright test -c playwright.reader.config.ts
npx playwright test -c playwright.config.ts e2e/curriculum-archive.spec.ts
npx vitest run src/api.auth.test.ts
```

完整 Reader 运行需设置 `EDISON_READER_TEST_EPUB` 为本机测试书路径，`EDISON_READER_LAYOUT_DIR` 为阶段 0 的布局 fixture 目录；否则扩展测试明确跳过。测试服务器、数据库和 headless 浏览器均隔离，不修改用户实际书库。

## 尚未覆盖

强制关闭、浏览器崩溃及系统回收前未确认的编辑仍可能丢失。尚无跨章节单条高亮、离线队列、自动冲突合并、撤销删除、锚点重绑、跨设备验收、全文检索与 Markdown/JSON 导出。大量批注的性能没有专项压测；当前快照保存与全书锚点核对方式不应直接声称适合无限规模。

下一阶段补上检索与导出：当前书正文查找及准确回跳、全库高亮/笔记查找、Markdown 和带内容版本/定位器的 JSON。Markdown 是阅读成果，JSON 才保留完整的范围身份。

本轮没有打开可见窗口或预览。headless 浏览器与临时服务器由测试框架关闭，相关端口已核对无遗留监听。源代码保持本地未提交状态，其他模块已有改动保留。
